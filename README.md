# 🧪 Lab Tracker — Система отслеживания лабораторных работ

## 📌 Описание проекта

**Lab Tracker** — это система для управления и отслеживания выполнения лабораторных работ по химии.

Платформа позволяет:

* студентам — сдавать лабораторные работы
* преподавателям — проверять и оценивать
* администраторам — управлять пользователями, группами и заданиями

Проект реализуется как **backend на Go + frontend на React** с архитектурой, приближенной к production.

---

## 🎯 Цель проекта

Разработать полноценную систему:

* с разграничением ролей
* с CRUD-операциями
* с системой сдачи и проверки работ
* с хранением файлов и оценок
* с возможностью масштабирования

---

## 👥 Роли пользователей

### 👨‍🎓 Студент

* Просмотр списка лабораторных работ
* Просмотр дедлайнов
* Сдача работы:

  * текстовый отчёт
  * загрузка файла (PDF, фото и т.д.)
* Просмотр оценок и комментариев

---

### 👨‍🏫 Преподаватель

* Просмотр работ своей группы
* Проверка отчётов студентов
* Выставление оценки
* Добавление комментариев
* Отправка на доработку
* Просмотр статистики группы

---

### 🛠 Администратор

* Управление пользователями
* Создание и редактирование групп
* Назначение преподавателей
* Управление лабораторными работами

---

## 🧩 Основные модули системы

### 📚 1. Управление группами

* Создание группы (название, курс, год)
* Назначение студентов
* Назначение преподавателя

---

### 🧪 2. Управление лабораторными работами

* Создание работы:

  * название
  * описание
  * цель
  * оборудование
  * реактивы
  * порядок выполнения
  * срок сдачи
* Прикрепление файлов (методички)
* Назначение работ группам

---

### ✍️ 3. Выполнение работы (студент)

* Список назначенных работ
* Отображение дедлайнов
* Форма сдачи:

  * текст
  * файл
* Кнопка **"Сдать на проверку"**
* После проверки:

  * оценка
  * комментарий

---

### ✅ 4. Проверка работ (преподаватель)

* Список сданных работ
* Просмотр отчёта (текст + файл)
* Выставление оценки:

  * 5-балльная / 100-балльная система
* Комментарий
* Действия:

  * ✔ Принять
  * 🔁 Отправить на доработку

---

### 📊 5. Журнал успеваемости

* Таблица:

  ```
  студент → лабораторная работа → оценка
  ```
* Метрики:

  * средний балл
  * количество сданных работ
* Экспорт (CSV / Excel)

---

### 🔐 6. Аутентификация

* Регистрация:

  * студент выбирает группу
  * преподаватель создаётся администратором
* Вход / выход
* Разграничение прав доступа

## 🏗 Архитектура проекта (Go)

Проект построен по принципам **чистой архитектуры**:

```
internal/
  handler/      # HTTP / API слой
  service/      # бизнес-логика
  repository/   # работа с БД

pkg/            # переиспользуемые компоненты
api/            # OpenAPI / protobuf
```

### Принципы:

* Разделение ответственности
* Использование интерфейсов
* Минимальная логика в handler
* Бизнес-логика только в service
* Repository отвечает только за БД

---

## 📂 Работа с файлами

* Файлы сохраняются в `/uploads`
* Имя файла:

  ```
  <timestamp>_<user_id>_<original_name>
  ```
* В БД хранится путь (`file_path`)

---

## 🔒 Безопасность

* Пароли:

  * `password_hash`
  * `password_verify` (или аналог в Go)
* Проверка ролей на каждом endpoint
* Ограничение доступа:

  * студент видит только свою группу
  * преподаватель — только свои группы

# Lab Tracker — документация проекта

## 1. Название проекта

**Lab Tracker** — система отслеживания лабораторных работ по химии.

## 2. Цель проекта

Цель проекта — разработать веб-приложение, которое позволяет студентам сдавать лабораторные работы, преподавателям проверять отчёты и выставлять оценки, а администратору управлять лабораторными работами и смотреть статистику.

Система решает следующие задачи:

* регистрация и авторизация пользователей;
* разделение доступа по ролям;
* управление лабораторными работами;
* назначение и сдача работ;
* проверка отчётов преподавателем;
* возврат работы на доработку;
* хранение оценок и комментариев;
* отображение прогресса студента;
* отображение статистики администратора;
* экспорт журнала сдач в CSV.

## 3. Используемые технологии

### Backend

* **Go** — основной язык backend-разработки;
* **Gin** — HTTP framework;
* **PostgreSQL** — база данных;
* **Goose** — миграции базы данных;
* **JWT** — авторизация пользователей;
* **bcrypt** — безопасное хеширование паролей;
* **OpenAPI** — описание HTTP API.

### Frontend

* **React** — пользовательский интерфейс;
* **Vite** — сборка frontend-приложения;
* **React Router** — маршрутизация;
* **Axios** — HTTP-запросы к backend.

### Инфраструктура

* **Docker Compose** — запуск базы данных, backend и миграций.

## 4. Роли пользователей

В системе реализованы три роли.

### Студент

Студент может:

* зарегистрироваться и выбрать группу;
* войти в личный кабинет;
* увидеть список назначенных лабораторных работ;
* посмотреть дедлайн по каждой работе;
* заполнить текст отчёта;
* прикрепить имя файла отчёта;
* отправить работу на проверку;
* увидеть статус работы;
* увидеть комментарий преподавателя;
* повторно отправить работу после возврата на доработку;
* увидеть оценку;
* посмотреть свой прогресс.

### Преподаватель

Преподаватель может:

* войти в систему;
* видеть работы студентов только своей группы;
* фильтровать работы по статусам;
* просматривать текст отчёта и файл;
* выставлять оценку;
* оставлять комментарий;
* вернуть работу на доработку;
* завершить проверку.

### Администратор

Администратор может:

* войти в административную панель;
* добавлять лабораторные работы;
* редактировать лабораторные работы;
* удалять лабораторные работы;
* просматривать статистику проекта;
* экспортировать журнал сдач в CSV.

## 5. Основной workflow сдачи работы

Для сдачи лабораторных работ используется жизненный цикл submission.

```text
draft -> submitted -> revision -> submitted -> reviewed
```

Описание статусов:

| Статус | Описание |
|---|---|
| `draft` | Работа ещё не отправлена. Студент может редактировать отчёт. |
| `submitted` | Работа отправлена на проверку. Редактирование запрещено. |
| `revision` | Преподаватель вернул работу на доработку. Студент снова может редактировать отчёт. |
| `reviewed` | Работа проверена. Оценка выставлена, работа заблокирована. |

Правила:

* студент не может повторно отправить работу в статусе `submitted`;
* студент не может редактировать работу в статусе `reviewed`;
* статус `revision` открывает возможность повторной отправки;
* при повторной отправке увеличивается номер попытки;
* после завершения проверки работа исчезает из вкладки преподавателя `На проверке`.

## 7. Архитектура backend

Backend построен по слоям:

```text
delivery/http -> service -> repository -> PostgreSQL
```

### `delivery/http`

HTTP-слой:

* принимает запросы;
* проверяет роль пользователя;
* валидирует базовые параметры;
* преобразует DTO в domain-модели;
* возвращает HTTP-ответ.

### `service`

Слой бизнес-логики:

* регистрация и вход;
* проверка дедлайнов;
* правила workflow сдачи;
* запрет повторной отправки;
* выставление оценки;
* расчёт прогресса;
* генерация CSV.

### `repository`

Слой доступа к данным:

* выполняет SQL-запросы;
* читает и записывает данные в PostgreSQL;
* не содержит бизнес-логики.

## 9. Установка и запуск

### 1. Подготовить `.env`

В корне проекта создать файл `.env`:

```env
POSTGRES_USER=lab_tracker
POSTGRES_PASSWORD=lab_tracker
POSTGRES_DB=lab_tracker
```

### 2. Запустить проект

```bash
make up
```

Команда запускает:

* PostgreSQL;
* миграции базы данных;
* backend-приложение.

Если нужно отдельно применить миграции:

```bash
docker compose run --rm migrator
```

Frontend будет доступен по адресу:

```text
http://localhost:3000
```

Backend API:

```text
http://localhost:8080/api/v1
```
